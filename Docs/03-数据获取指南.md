# 数据获取指南

本文档记录各数据维度的系统来源、命令行验证方式与 IOKit 编程接口。所有命令均已在本机（Apple Silicon，macOS 26）验证可用。

## 总览

| 维度 | 准确度 | 来源 |
| --- | --- | --- |
| USB 协商速率 | 精确 | IOKit `IOUSBHostDevice` |
| 充电功率/PD 合同 | 精确 | IORegistry `AppleSmartBattery` |
| USB-C 端口状态/插拔方向 | 精确（Apple Silicon） | IORegistry `AppleHPMInterfaceType*` / `AppleTCControllerType*` |
| 线缆 e-marker（速度档/电流评级/厂商） | **精确直读**（Apple Silicon） | `IOPortTransportComponentCCUSBPDSOPp`（SOP'） |
| 充电器 PD 档位表 + 当前协商档 | 精确（Apple Silicon） | `IOPortFeaturePowerSource` |
| 显示器/DP 链路 | 精确 | CoreGraphics + IORegistry |
| 雷电路径/带宽 | 精确 | `IOThunderboltPort` / SPThunderbolt |
| 线缆规格（无 e-marker 时） | 推断 | CableRatingEngine 历史峰值 |

## 一、USB 传输速度

### 命令行验证

```bash
system_profiler SPUSBDataType -json      # 结构化 USB 设备树
ioreg -p IOUSB -l -w 0                   # IORegistry 原始数据
```

### 关键属性

| 属性 | 含义 |
| --- | --- |
| `kUSBDevicePropertySpeed` | 协商速率 bps：480000000=USB2 Hi-Speed，5000000000=5G，10000000000=10G，40000000000=USB4/雷电 |
| `bcdUSB` | USB 规范版本 |
| `kUSBVendorID` / `kUSBProductID` | 厂商/产品 ID |
| `kUSBDevicePropertyLocationID` | 物理端口定位（聚合历史数据时的 key） |
| 控制器节点 `UsbIOPort` | 设备祖先链上的完整路径，末段即物理端口名（`Port-USB-C@1`）——**设备↔端口配对的权威来源** |

### 实测注意（真机验证）

- 内置根 hub 类设备（如 "USB2.1 Hub"）**没有 `Speed` 和 `LocationID` 属性**，位置只编码在路径末段的 `@unit`（`…/USB2.1 Hub@00100000`）——需要从 `IORegistryEntryGetPath` 回退解析。
- 无设备插入时枚举为空是正常现象。

### 编程接口

```swift
let iterator = IOIteratorMake...
// matching: IOServiceMatching("IOUSBHostDevice")
// 读取: IORegistryEntryCreateCFProperties → speed / bcdUSB / ...
```

### 实测吞吐（已实现，CLI + App UI）

协商速率 ≠ 实际吞吐。`ThroughputTester`（`Sources/CableKit/Throughput/ThroughputTester.swift`）对挂载卷做写→落盘 / 顺序读两阶段基准（默认每阶段 5 秒，4 MiB 块，MB/s 十进制口径），CLI `throughput` 子命令（`--volume` 选卷、`--seconds` 调时长）与 App 主窗口「吞吐实测」区（`ThroughputSectionView`）共用同一套 CableKit 逻辑。**不与线缆会话绑定**——macOS 不暴露"USB 存储设备 → 挂载卷"的直接映射，App 端由用户在候选卷列表中手动选择。

## 二、充电能力（信息最丰富）

### 命令行验证

```bash
ioreg -rn -c AppleSmartBattery    # 核心：AdapterVoltage / Amperage / AdapterDetails
pmset -g batt                     # 电量与电源状态概览
system_profiler SPPowerDataType   # 电池健康、适配器概览
```

### 关键属性（`AppleSmartBattery`）

| 属性 | 含义 |
| --- | --- |
| `AdapterVoltage` × `Amperage` | 当前充电电压(mV)×电流(mA) → 功率 W |
| `AdapterDetails` | 字典：适配器描述、PD 版本、negotiated 合同 |
| `CurrentCapacity` / `MaxCapacity` | 电量百分比 |
| `CycleCount` / `MaximumCapacity` | 电池健康 |

### 编程接口

- 一次性读取：`IOServiceGetMatchingService(kIOMainPortDefault, IOServiceMatching("AppleSmartBattery"))`
- 实时曲线：`IOServiceAddInterestNotification(kIOInterestNotifications, ...)` 监听属性变化 —— **用通知而非轮询**
- 电量/电源源：`IOPSCopyPowerSourcesInfo` + `IOPSGetPowerSourceDescription`

## 三、USB-C 端口控制器（Apple Silicon，2026-09-13 新增）

Apple Silicon 的 USB-C / MagSafe 端口由 `AppleHPM` 驱动族管理，registry 上每个物理端口一个节点，
子树携带 e-marker、PD 档位与插拔状态。**本机（M4）实测结构：**

```
Port-USB-C@1            ← AppleHPMInterfaceType10（USB-C）/ Type11（MagSafe 3）/ 老机型 AppleTCControllerType10/11
├─ CC                   ← IOPortTransportStateCC
│  ├─ SOP               ← IOPortTransportComponentCCUSBPDSOP：对端设备（充电器/坞站）的 Discover Identity
│  └─ SOP'              ← IOPortTransportComponentCCUSBPDSOPp：线缆近端 e-marker 的 Discover Identity
└─ Power In             ← IOPortFeaturePowerIn
   └─ USB-PD            ← IOPortFeaturePowerSource：PD 档位表 + WinningPowerSourceOption（当前协商档）
```

### 命令行验证

```bash
ioreg -r -c AppleHPMInterfaceType10 -l          # USB-C 端口状态（PortTypeDescription/ActiveCable/PlugOrientation/Transports*）
ioreg -r -c IOPortFeaturePowerSource -l         # PD 档位（PowerSourceOptions / WinningPowerSourceOption）
ioreg -r -c IOPortTransportComponentCCUSBPDSOPp -l   # 线缆 e-marker
```

### 关键属性

| 节点 | 属性 | 含义 |
| --- | --- | --- |
| 端口 | `PortTypeDescription` | "USB-C" / "MagSafe 3" |
| 端口 | `ConnectionActive` / `ActiveCable` | 有连接 / 检测到线缆 |
| 端口 | `PlugOrientation` | 1/2 = 正/反插 |
| 端口 | `TransportsSupported`（含 `CIO`） | 是否具备 USB4/雷雳数据能力 |
| 端口 | `Description` | 路径名 `Port-USB-C@1`（= `UsbIOPort` 末段，配对 key；`IORegistryEntryGetName` 不含 @N） |
| SOP' | `Vendor ID` / `Product Type Description` | e-marker 厂商（0 = 未上报）；"Passive Cable"/"Active Cable"/EPR |
| SOP' | `Metadata.VDOs` | 原始 VDO（Data，**线上小端序**）；Cable VDO = 第 4 个对象 |
| USB-PD | `PowerSourceOptions` | PD 档位表——**实测返回无序 NSSet（__NSCFSet），不是数组** |
| USB-PD | `WinningPowerSourceOption` | 当前协商档（含 UUID，与档位表配对） |

### Cable VDO 位段（USB-PD R3.2，与 Linux 内核 pd_vdo.h 一致，已真机验证）

- bits [2:0] 线缆速度：0=USB2，1=USB 3.2 Gen1，2=Gen2，3=USB4 Gen3(40G)，4=USB4 Gen4(80G)
- bits [6:5] 电流评级：0=默认 USB，1=3A（≤60W），2=5A（≤100W）
- ID Header VDO bits [29:27] 产品类型：3=Passive Cable，4=Active Cable，6=VPD

### 编程接口注意（真机踩坑记录）

1. `IORegistryEntryGetChildEntry` 在这些 IOPort 节点上**返回成功但空迭代器**；必须用
   `IORegistryEntryCreateIterator(entry, kIOServicePlane, kIORegistryIterateRecursively, …)` 遍历子树。
2. `PowerSourceOptions` 是 **CFSet**（无序）：`as? [Any]` 失败，需 `as? NSSet` 桥接后按电压排序。
3. VDO 的 Data 是**线上小端序**：`UInt32(littleEndian:)` 解读才与 Apple 平铺字段自洽。
4. App Sandbox 下（`app-sandbox` + `device.usb`）以上读取与明文权限结果一致（Gate A 已验证），商店版可用。
5. Intel 机型 / 无 AppleHPM 节点时枚举为空——属正常，走评级引擎推断兜底。
6. e-marker 只在线缆插入且 partner 上电后才可能响应（VCONN 供电），无 e-marker 的廉价线 SOP' 节点为空。

## 四、视频传输能力

### 命令行验证

```bash
system_profiler SPDisplaysDataType -json          # 显示器、分辨率、（内置屏才有）link rate、HDR
ioreg -c IOPortTransportStateDisplayPort -l -r     # DP 传输链路：归属端口 + EDID 身份 + 链路速率
CGGetOnlineDisplayList                             # （API）在线显示器
```

### 关键信息

- 在线显示器列表（`DisplayService`，CoreGraphics 直读）：分辨率 / 刷新率 / 是否内置 /
  `CGDisplayVendorNumber` `CGDisplayModelNumber` `CGDisplaySerialNumber`（EDID 身份，用于下面的匹配）。
- **外接显示器归属到具体物理端口**（`DisplayPortTransportService` + `PortGrouping.displayPortLinks`）：
  `IOPortTransportStateDisplayPort` 节点只在端口当前确有显示器接入、DP 交替模式生效时才存在，
  自带 `TransportDescription`（形如 `"Port-USB-C@1/DisplayPort"`），去掉 `/DisplayPort` 后缀就是
  `USBCPortSnapshot.portID`——不需要像端口能力位（`TransportsProvisioned` 含 `DisplayPort`）那样
  "猜恰好一个口在跑 DP"，端口控制器自己上报了归属关系。真机验证（本机外接 AOC U27U3XD）：
  ```
  TransportDescription = "Port-USB-C@1/DisplayPort"
  Active = Yes / Tunneled = No
  LinkRateDescription = "8.1 Gbps (HBR3)"        ← 比 system_profiler 尽力而为解析更可靠，本机验证恒有值
  ManufacturerName = "AOC" / ProductName = "U27U3XD" / ProductID = 9987 / SerialNumber = 393
  ```
- **精确匹配到具体 `CGDirectDisplayID`**（`PortGrouping.matchedDisplay`）：节点自带的 EDID
  Product ID 必须等于 `CGDisplayModelNumber`，且双方都上报厂商时 `CGDisplayVendorNumber` 解出的
  3 字母 PNP 码也要一致；命中不唯一（如坞站带两台同型号显示器）或缺身份信息时返回 nil——
  宁可只展示链路本身已知的厂商/型号，也不把分辨率/刷新率瞎连到错的屏幕。
- DisplayPort 链路速率：HBR2 / HBR3 / UHBR10 / UHBR20 → 决定 4K@60、8K 等能力上限。
- 一个物理口经坞站级联可能同时驱动多台显示器：`PortGrouping.displayPortLinks` 按端口返回数组，
  不假设一口一屏。
- 原生 HDMI 口（部分机型，无对应 AppleHPM 端口节点）：`TransportDescription` 不是
  `"Port-*/DisplayPort"` 形状，`DisplayPortTransportParsing.portID` 返回 nil，不强行编出归属——
  v1 暂不支持这类口的显示器归属。

## 六、线缆规格规则（直读 + 推断）

**直读优先**（Apple Silicon，SOP' 有身份时）：

| 直读字段 | 含义 |
| --- | --- |
| `Product Type Description` | 被动/主动/EPR 线缆 |
| Cable VDO bits [2:0] | 线缆速度档（USB2 → 80Gbps） |
| Cable VDO bits [6:5] | 3A / 5A 电流评级 |
| `Vendor ID` = 0 | e-marker 未上报厂商（可信度信号，措辞"看起来不寻常"而非"假线"） |

**推断兜底**（无直读数据时的历史峰值规则）：

| 观测到的协商结果 | 可推断的线缆规格 |
| --- | --- |
| USB 协商 480Mbps | 仅 USB 2.0 线（无屏蔽差分对） |
| 协商 5G/10Gbps | 至少 USB 3.x 认证线 |
| 协商 40Gbps（USB4/雷电） | 满速数据线 |
| PD 合同 20V×5A（100W+） | **带 e-marker 的 5A 线**（≤3A 线物理上无法协商到 5A） |
| DP 协商 UHBR/HBR3 | 支持 4K@60 及以上的视频线 |

**聚合方式**：以线缆会话（`CableSession.id`，物理端口键）为 key 记录历史峰值；插拔不同设备只会抬高而非清零评级。产品话术中必须使用"至少支持/推断"措辞，不得虚构品牌认证。

## 七、注意事项

1. `SPUSBDataType` 在无设备时返回空数组是正常现象（本机已验证）。
2. Apple Silicon 与 Intel 的 registry 树结构有差异，适配层需按 `#if arch(arm64)` 或运行时检测分支处理；端口控制器层仅 Apple Silicon 有效。
3. 不解析 PD 原始报文：读系统已解析好的字段（AppleHPM 平铺属性 / VDO 标准位段）即可，报文级解析脆弱且无必要。
4. 快照数据结构：`CableSnapshot { timestamp, usbDevices[physicalPortID], power, displays, thunderboltDevices, sessions[CableSession], ports[USBCPortSnapshot], displayPortLinks[DisplayPortLinkSnapshot] }`，Codable 落盘。
