## 二、模块职责

### 1. IOKit 适配层（系统访问，唯一触碰系统 API 的层）

| 服务 | 系统接口 | 获取内容 |
| --- | --- | --- |
| `USBService` | `IOServiceGetMatchingServices(kIOUSBHostDevice)`、`IORegistryEntryCreateCFProperties` | 协商速率（`kUSBDevicePropertySpeed`）、`bcdUSB`、Vendor/Product ID、设备树；沿祖先链 `UsbIOPort` 配对物理端口 |
| `PowerService` | `AppleSmartBattery` IORegistry + `IOPSCopyPowerSourcesInfo` + `IOServiceAddInterestNotification` | `AdapterVoltage`×`Amperage`→功率、`AdapterDetails`（PD 版本/协议）、电量 |
| `PortControllerService` | `AppleHPMInterfaceType*` / `AppleTCControllerType*` 子树（`IORegistryEntryCreateIterator` 递归） | 端口状态/插拔方向/传输能力、e-marker（SOP' + Cable VDO 解码）、PD 档位表与当前协商档（`IOPortFeaturePowerSource`） |
| `DisplayService` | `CGGetOnlineDisplayList`、system_profiler SPDisplaysDataType 对应的私有读取路径 | 显示器列表、分辨率/刷新率、DP 链路速率（HBR2/3、UHBR10/20） |
| `ThunderboltService` | `IOServiceMatching("IOThunderboltPort")` / SPThunderboltDataType | 雷电路径、PCIe 带宽 |
| 插拔事件 | 内容签名差分（1.5s 轮询，事件化输出见 `snapshotStream`） | USB/电源/端口变化触发快照事件（`IOServiceAddInterestNotification` 事件驱动为规划项） |

要点：所有 IOKit 调用封装在一个 Swift Package（如 `CableKit`）里，向上暴露纯 Swift 的值类型（`CableSnapshot`），方便单测（mock 数据）和 CLI 复用。

### 2. 业务层

- **CableMonitor**：单例调度器。收到插拔事件 → 并发调用各 Service → 组装 `CableSnapshot` → 发布给 UI 与持久化。
- **CableRatingEngine**（差异化核心）：
  - 输入：历史 `CableSnapshot` 序列（按端口聚合）
  - 输出：线缆能力卡 `USB4 / 40Gbps ⚡ 100W(5A, 有 e-marker) 🖥 4K@60`
  - 规则示例：曾协商 10Gbps → 至少 USB 3.1 Gen2 线；曾出现 `AdapterVoltage` 20V + 5A 合同 → 线为 e-marker 5A 线
- **ThroughputTester**（可选）：对挂载卷读写大文件 5 秒测实际吞吐，标注"实测值 ≠ 协商值"。

### 3. 表现层

- **MenuBarExtra**：图标随状态变化（充电中显示功率数字/波形），点开快捷面板。
- **主窗口**：三栏式——端口列表 / 当前连接快照 / 能力卡 + 实时功率曲线（Swift Charts）。
- **通知**：`UNUserNotificationCenter`，插线时弹"已连接：USB4 40Gbps ⚡ 60W"。

## 三、数据流

```
热插拔/定时/手动刷新
   → CableMonitor 触发
   → 各 Service 并发拉取（async/await，IOKit 调用放后台队列）
   → 合成 CableSnapshot（值类型，Codable）
   → ① UI 订阅渲染  ② CableRatingEngine 更新评级  ③ 持久化为 JSON/SwiftData 记录
```

## 四、工程结构

```
cablescope/
├── CableKit/               # 系统 IO 适配层（Swift Package，可独立测）
│   ├── USB/  Power/  Display/  Thunderbolt/
│   └── Models/CableSnapshot.swift
├── CableScope/             # 主 App
│   ├── App/                # 入口、MenuBarExtra、生命周期
│   ├── Views/              # 能力卡、曲线、端口列表
│   ├── ViewModels/         # CableMonitor、评级引擎桥接
│   └── Persistence/        # 快照库
├── cablescope-cli/         # CLI（复用 CableKit，开发期验证数据边界）
└── Tests/
```

**开发顺序**：① CLI 先行验证 IOKit 数据边界 → ② 快照 UI → ③ 实时监控与曲线 → ④ 评级引擎 → ⑤ 自启动/通知/公证打磨。详细数据获取方法见《03-数据获取指南.md》。

## 五、关键技术决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 语言/框架 | Swift + SwiftUI | 数据全在 IOKit/CoreFoundation，原生路径最短 |
| 架构模式 | 分层 + 单向数据流 | IOKit 适配层隔离系统 API，业务可 mock 可测 |
| UI 形态 | 菜单栏 + 主窗口 | 此类监控工具的天然形态 |
| 持久化 | SwiftData（fallback JSON） | 历史峰值是评级引擎的输入，必须落盘 |
| 并发 | Swift Concurrency（async/await + AsyncStream 包装 IOService 通知） | 现代且与 SwiftUI 绑定自然 |

## 六、风险与约束

- **e-marker 直读（2026-09-13 已实现）**：Apple Silicon 上经 AppleHPM 的 SOP' 节点直读线缆身份（速度档/电流评级/产品类型），UI 仍标注数据来源；无 e-marker 的线缆回退历史峰值推断，措辞用"至少支持/推断"，不虚构品牌认证。
- **Apple Silicon 与 Intel 的 registry 键名有差异**：端口控制器层（AppleHPM/AppleTC）仅 Apple Silicon 有效，Intel 上枚举为空需降级到推断模式；适配层按运行时检测分支。
- **权限**：IORegistry 概览信息无门槛；Gate A 已验证端口控制器读取在 App Sandbox（`app-sandbox` + `device.usb`）下可用；macOS 14.2+ 连接部分 USB 配件可能触发系统"允许配件连接"设置，需在文档/FAQ 说明。
- **雷电与 USB4 混合协商状态复杂**：v1 展示系统 negotiated 结果 + AppleHPM 预解析字段，不解析 PD 原始报文。
- **IORegistry 编程陷阱**（真机踩坑，详见 Docs/03）：IOPort 节点 `GetChildEntry` 返回成功但空迭代器，须用递归迭代器；`PowerSourceOptions` 是 CFSet 非数组；VDO 为线上小端序；内置 hub 无 LocationID/Speed 属性。
