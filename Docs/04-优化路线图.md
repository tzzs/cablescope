# 优化路线图（对标 whatcable）

> 2026-09-13 定稿、2026-09-19 清理。背景：对标 [whatcable](https://github.com/darrylmorley/whatcable)（macOS USB-C 检测工具）后的差距分析与优化计划；产品决策为**全量开源、无付费版、双渠道分发**。
>
> 本文只保留**仍需推进**的内容。已完成里程碑压缩为下面的速览表——实现细节见 git history（按里程碑日期查），长期有效的设计约束已沉淀到 `AGENTS.md`（分层规则、CableMonitor 事件模型、`TTLCache`、本地化红线、文案红线）与各文件的头部注释。

## 一、产品与分发模型（定稿）

- **不做付费版**：全功能开源（MIT，避开 GPL×MAS 不兼容红线），可持续性走可选捐赠。
- **双渠道同一代码库**：差异只来自 Apple 硬规则，不人为阉割——
  - **外部版**（主渠道）：全功能含 CLI；Homebrew（cask 装 App + formula 装 CLI）/ GitHub Releases notarized DMG。
  - **商店版**（可选、低优先）：MAS 上架，受规则自然受限——不带 CLI（Guideline 2.4.5）、必须 App Sandbox。Gate A 已验证 AppleHPM 读取在 sandbox 下可用，端口层数据双版本通用。
- 评级引擎、功率历史、插拔通知等功能**不做任何版本/付费门控**。

## 三、待推进事项

### A. 只差执行（无技术阻塞，需要仓库 owner 操作）

**首次正式发布尚未发生。** 远程仍无任何 tag 与 release，而两份 README 的安装章节已经写了 `brew install --cask tzzs/tap/cablescope` 并声称装的是公证过的 app——用户照做会失败。完整链路（release.yml → bundle_app.sh → DMG → 公证 → gh release → 同步 cask 到 tap 仓库）代码侧已就绪且本地实弹跑通过，缺的是：

1. 配置 GitHub 仓库 secrets：`APPLE_ID` / `APPLE_TEAM_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `DEVELOPER_ID_APPLICATION`（缺失时 release.yml 会跳过公证，产出未公证 DMG）。
2. **决定版本号走哪条路**：本地有一个 2026-09-14 打的 `v0.1.0` tag（从未 push），而 release-please 另开了一个 0.2.0 的 release PR——两条路径并存，需要选一条：push 旧 tag 发 0.1.0，还是走 release-please 直接发 0.2.0（选后者的话建议删掉本地那个 tag 以免混淆）。
3. 发布后回填：cask 的 `sha256: :no_check` 换成实际值；formula `version` 随发版更新。

### B. CI 覆盖不到 Xcode 构建路径

`CableScopeWidget` 不在 `Package.swift` 里，所以 `swift build` 从不编译它；CI 也从不跑 `xcodegen generate` + `xcodebuild`。这意味着**产品的一部分没有任何自动化检查守着**：CableKit 的 API 变化（改签名、去掉默认参数、重命名类型）可以一路绿灯合并，直到某个人手工重新生成 Xcode 工程时才炸出来。同理，AppStore config（sandbox entitlements 那条路径）目前也只有手工验证过。

2026-09-19 实测：`xcodegen generate` + `xcodebuild -scheme CableScopeWidget` 与 `-scheme CableScopeApp` 均 **BUILD SUCCEEDED**，所以现在没有坏——缺的是守住它的检查。增量构建 7.6s，CI 加一步的成本相对现有 ~51s 的 CI 很低。

### C. 代码已就位，等真机/日常使用验证

- **Widget 桌面渲染实弹**：真机添加 Widget 需有效签名，待签名 App 日常使用中观察。
- **插拔通知横幅实弹**：同上。
- **TB5 非对称 120G 代际识别复核**：M6 已把映射从子串匹配改为"提取数值取最大"并有单测覆盖，但真机复核要等手头有 TB5 非对称外设。

### D. 需要 Apple Developer 后台配置

- **Widget 偏好联动（主题 + 语言）**：Widget 源码里没有任何 `UserDefaults`/`AppPreferences` 引用，即**完全读不到 App 的偏好设置**——不止早先记录的主题，语言同样不生效：它调用 `DiagnosticsEngine.portHeadline` 时不传 `locale:`，走默认的 `.current`（系统语言）。所以用户在 App 里选了 English 而系统是中文时，Widget 仍显示中文头条。两者是同一个修复：App Group + `UserDefaults(suiteName:)` 共享偏好，需新增 entitlements 并在 Apple Developer 后台注册 App Group。
- **MAS 提审**：材料已就绪（`Packaging/privacy/PrivacyInfo.xcprivacy`、`Packaging/entitlements/mas.entitlements`，sandbox 端到端验收已通过），提审本身未做。定位为可选、低优先。

### E. 外部数据阻塞（含集成设计与触发条件）

这三项都不是能力问题，而是拿不到可靠数据源。**设计已预研，数据到位前不引入无数据可测的死代码。**

**XID 认证核查**
- 数据源：USB-IF XID 认证清单，离线获取未果，待社区提供。
- 集成设计：`usb-vendors.json` 条目扩展可选 `xid` 字段；`EMarkerSnapshot` 的 VID + productType 与清单匹配后，由 `EMarkerTrust` 新增 note case（如 `.certifiedMatch`）渲染"认证在册"提示——措辞仍守红线：**在册 ≠ 真伪判决**。

**dock 中间 hub 身份标注**
- 已落地：雷雳子树深度缩进（`ThunderboltDeviceSnapshot.depth`）。
- 剩余：链路中间 hub 的身份标注（名称/端口）——`system_profiler` 不暴露中间 hub 的稳定标识，待找到可靠数据源。

**线缆电阻估算**
- 估算需"合同电压 − 远端电压 = 压降"，而：远端（设备侧）电压 macOS 不暴露；顶层 `Amperage` 是**整机**抽流非端口值（多线时无法归属到线）；PPS/AVS 原始报文缺失（`PDOPortPowerSnapshot` 仅平铺档位）；电池侧微小放电会混入电流读数。
- **触发条件**：拿到端口级电流读数或远端电压感知数据（如雷雳坞站电压上报）后重启此项目。

### F. 远期 / 低优先

- **TUI dashboard**：对标项里唯一没做的形态，优先级低（CLI 的 `watch` 已覆盖大部分使用场景）。

## 四、真机踩坑记录（实现时必读，详见 Docs/03）

1. IOPort 节点 `IORegistryEntryGetChildEntry` 返回成功但空迭代器 → 用 `IORegistryEntryCreateIterator` + `kIORegistryIterateRecursively`。
2. `PowerSourceOptions` 是 CFSet（__NSCFSet）不是数组 → `as? NSSet` 桥接，按电压排序展示。
3. VDO Data 是线上小端序 → `UInt32(littleEndian:)`，已与 Apple 平铺字段交叉验证。
4. 内置根 hub 无 `LocationID`/`Speed` 属性 → 路径末段 `@hex` 回退。
5. `IORegistryEntryGetName` 不含 `@N` 位置段 → 端口 ID 用 `IORegistryEntryGetPath` 末段。
6. 端口节点上的 `SOPMfgString`（"Realtek"）是 HPM 控制器芯片厂商（RTBuddy），**不是**线缆 e-marker 厂商；e-marker 厂商看 SOP' 节点的 `Vendor ID`。
7. 经典 SwiftPM 构建引擎（CI 在用）不编译 `.xcstrings`，英文表必须是手写的经典 `.strings`；相关红线见 `AGENTS.md`「Localization」章节。
