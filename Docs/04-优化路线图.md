# 优化路线图（对标 whatcable）

> 2026-09-13 定稿。背景：对标 [whatcable](https://github.com/darrylmorley/whatcable)（macOS USB-C 检测工具）后的差距分析与优化计划；产品决策为**全量开源、无付费版、双渠道分发**。

## 一、产品与分发模型（定稿）

- **不做付费版**：全功能开源（License 选 MIT/Apache-2.0，避开 GPL×MAS 不兼容红线），可持续性走可选捐赠。
- **双渠道同一代码库**：差异只来自 Apple 硬规则，不人为阉割——
  - **外部版**（主渠道）：全功能含 CLI；Homebrew（cask 装 App + formula 装 CLI）/ GitHub Releases notarized DMG；更新用 Sparkle 或 brew。
  - **商店版**（可选、低优先）：MAS 上架，受规则自然受限——不带 CLI（Guideline 2.4.5）、必须 App Sandbox。Gate A 已验证 AppleHPM 读取 sandbox 可用，端口层数据双版本通用。
- 评级引擎、功率历史、插拔通知等功能**不做任何版本/付费门控**。

### M1 端口控制器数据层 ✅（2026-09-13 完成）

- ✅ 模型：`USBCPortSnapshot`（端口状态/方向/传输能力）、`EMarkerSnapshot`（VID/产品类型 + Cable VDO 解码：速度档、3A/5A 评级）、`PartnerIdentitySnapshot`（SOP 对端身份）、`PDOPhase` + `PDOPortPowerSnapshot`（档位表 + Winning 配对）。
- ✅ `PortControllerService`：枚举 AppleHPMInterfaceType10/11/12/18 + AppleTCControllerType10/11，递归迭代器遍历子树收集 SOP/SOP'/USB-PD 节点。
- ✅ USB 设备↔物理端口配对：祖先链 `UsbIOPort` 路径 → `physicalPortID`，`CableSession` 携带并配对端口快照；内置 hub 无 LocationID 时回退路径末段 @hex。
- ✅ 接线：CableMonitor 第 5 路 fan-out、内容签名、快照 JSON（Codable 兼容旧 JSON 缺失键）。
- ✅ UI：整机概览 PD 档位表（当前档高亮）+ 充电诊断行；线缆卡片 e-marker 胶囊；会话详情端口状态块。
- ✅ CLI：pretty 增加端口状态行与 PD 档位行（`*` 标当前档）；属性检查器类清单加 AppleHPM/IOPortFeaturePowerSource/SOP'。
- ✅ 降级：无 AppleHPM 节点（Intel/老机型）→ ports 空 + 推断模式不变。

## 三、真机踩坑记录（实现时必读，详见 Docs/03）

1. IOPort 节点 `IORegistryEntryGetChildEntry` 返回成功但空迭代器 → 用 `IORegistryEntryCreateIterator` + `kIORegistryIterateRecursively`。
2. `PowerSourceOptions` 是 CFSet（__NSCFSet）不是数组 → `as? NSSet` 桥接，按电压排序展示。
3. VDO Data 是线上小端序 → `UInt32(littleEndian:)`，已与 Apple 平铺字段交叉验证。
4. 内置根 hub 无 `LocationID`/`Speed` 属性 → 路径末段 `@hex` 回退。
5. `IORegistryEntryGetName` 不含 `@N` 位置段 → 端口 ID 用 `IORegistryEntryGetPath` 末段。
6. 端口节点上的 `SOPMfgString`（"Realtek"）是 HPM 控制器芯片厂商（RTBuddy），**不是**线缆 e-marker 厂商；e-marker 厂商看 SOP' 节点的 `Vendor ID`。

## 五、阻塞项集成设计与触发条件

### XID 认证核查（外部数据阻塞）

- **数据源**：USB-IF XID 认证清单，离线获取未果，待社区提供。
- **集成设计**：`usb-vendors.json` 条目扩展可选 `xid` 字段（如 `{"vid": "0BDA", "name": "Realtek", "xid": ["..."]}`）；`EMarkerSnapshot` 的 VID + productType 与清单匹配后，由 `EMarkerTrust` 新增 note case（如 `.certifiedMatch`）渲染"认证在册"提示——措辞仍守红线：**在册 ≠ 真伪判决**。
- **现状**：模型无 XID 字段；数据未到位前不引入无数据可测的死代码。

### dock 中间 hub 身份标注（部分顺延）

- 已落地（M6）：雷雳子树**深度缩进**（`depth`）。剩余：链路中间 hub 的身份标注（名称/端口）——system_profiler 不暴露中间 hub 的稳定标识，待找到可靠数据源。

### 线缆电阻估算（数据缺口，顺延）

- 估算需"合同电压 − 远端电压 = 压降"，而：远端（设备侧）电压 macOS 不暴露；顶层 `Amperage` 是**整机**抽流非端口值（多线时无法归属到线）；PPS/AVS 原始报文缺失（`PDOPortPowerSnapshot` 仅平铺档位）；电池侧微小放电会混入电流读数。
- **触发条件**：拿到端口级电流读数或远端电压感知数据（如雷雳坞站电压上报）后重启此项目。
